# Angelica and the Java 25 server: what adopting them costs

Written 2026-10-17. It follows the 2026-10-16 modernization report
(https://claude.ai/artifact/Tuv1zju2ASCLDgWcXHX1FD) and runs that report's
"Before deciding" tests. Nothing here has been installed in the live instance,
the play server or a release. Every run happened in the isolated dirs
`C:\qfb\client` (OptiFine E7), `C:\qfb\client-ang` (Angelica stack),
`C:\qfs\trial-base` (Java 8 server) and `C:\qfs\trial-c` (Java 25 + lwjgl3ify
server). Each dir was put back the way it was found afterwards. The two
servers' disposable bench worlds were regenerated by the benches, and test
worlds were deleted.

"Angelica stack" means Angelica 2.2.33, UniMixins 0.3.2, GTNHLib 0.11.54,
Hodgepodge 2.7.216, ArchaicFix 0.8.0 and GTNH CodeChickenCore 1.4.22 on Forge
10.13.4.1614, with OptiFine, FastCraft and BetterFps removed. "Java 25 server"
means Temurin 25.0.4 + lwjgl3ify 3.0.39 (forgePatches launcher).

## Bottom line

**Angelica on the client costs about 11–16 hours.** Most of that is porting
the splash screen and music (6–10 h). The rest is the IrisApi shader check
(2 h), packaging and launcher (1–2 h), key bindings and Angelica's frame pacer
(1 h), and a 30-minute hand test of portals, transforming and MCHeli rotors.
Sharing a slim server adds about 1 h: an fps check of Angelica without
Hodgepodge.
Add 2–4 h if Psychedelicraft's drug overlays must keep working; their shaders
don't compile under Angelica. These go for good: Better Snow, OptiFine's Smooth
FPS, Fast Render and Fast Math, and play on GPUs without OpenGL 3.3 (Intel HD
2000/3000), which need an E7 fallback. The splash and music are lost until
they're ported. Nothing in the at-risk list broke on screen.

**The Java 25 server costs about 4–6 hours** plus one survey rerun: the new
launch line (1–2 h), Recurrent Complex's Gson fix (2–3 h) and AsieLib's
nicknames (0.5 h). Lucky Block is already fixed and committed. The gain doesn't
depend on Hodgepodge: total GC pause −68% and the worst stall drops from
~1.1 s to ~0.26 s with or without it. Hodgepodge/ArchaicFix add only faster
chunk generation (+34% vs +8% over Java 8) and a faster boot.

**Can they be adopted separately? Yes, but only in one shape.** If the server
runs Hodgepodge, ArchaicFix or GTNHLib, every client must run them too.
GTNHLib crashes OptiFine E7, so the server and the Angelica rollout become one
step and E7 clients (the GL 3.3 fallback included) are locked out. The shape
that separates them:

- Server: Java 25 + lwjgl3ify + UniMixins, **without** Hodgepodge, ArchaicFix
  or GTNHLib. Stock E7 clients joined it and passed every check (test 1).
- If Angelica clients are to join too, everyone, server included, swaps
  CodeChickenCore + CodeChickenLib for GTNH CodeChickenCore 1.4.22. Otherwise
  NEI's packets don't match and Angelica clients are kicked. With that one jar
  swapped, E7 and Angelica-without-Hodgepodge clients both joined the same
  Java 25 server.
- An Angelica client that keeps Hodgepodge can't join a server without it
  (packet 53 mismatch). Angelica's measured gains were taken with Hodgepodge
  and ArchaicFix in, so the Angelica-without-Hodgepodge fps is unmeasured.

So the order with the least risk: move the server to slim Java 25 now. It
needs no client change and keeps the whole GC win. Swap everyone to GTNH
CodeChickenCore when the Angelica client is ready. Decide later whether to
make Hodgepodge mandatory on both sides for its chunk-generation gain.

**A Java 25 client** works after a 1 h CustomMenu patch and a new launcher
(2–3 h). Audio, keybinds, Carpenter's Blocks and Decocraft were all fine. The
only measured gain is a faster boot (61 s vs 73–80 s), so it can wait.

## Every cost

Status key: **fixed** (done and committed), **config** (a setting or a jar
swap), **small patch** (a qf-tweaks transformer or a few lines in our mods,
with an hour estimate), **needs work** (with an estimate), **blocker** (stops
something until it is solved). Hours are for writing plus one test boot.

## The tests

All client tests used a throwaway Forge mod (`qfscriptprobe`, source in the
evidence folder) that runs a script once the player is in a world. It only does
what a player can do: chat commands, clicks, the creative inventory, key
bindings, looking around, screenshots. World changes go through commands, never
through the client thread. Each launch was preceded by `trial.py status` and a
check that no other client was running; the heap total stayed at or under 21 GB.
The census servers on `C:\qfs\c1`/`c2` ran throughout, so the CPU was loaded.

### Test 1: mismatched join. Pass for a slim server, fail for the full stack

Server `C:\qfs\trial-c`, Java 25 + lwjgl3ify, 4 GB, fresh world. Client
`C:\qfb\client` = today's OptiFine E7 client (release qf-content, Morph added),
Java 8, 6 GB.

|---|---|---|

- Mod entities: `TragicMC.Jabba`, `TragicMC.Tox`, `witchery.goblin` and

the server it is a required mod (rejection above), and with it on an E7 client

take OptiFine clients at all. lwjgl3ify and UniMixins on their own are accepted
by a client that lacks them.

**The coupled path** (added today, not in the original list): the Angelica

So the stack works end to end. It just has to be adopted on both sides at once.

### Test 3: Java 25 client. Boots after one fix

The Angelica stack plus lwjgl3ify 3.0.39 on Temurin 25.0.4, launched the way
lwjgl3ify's Prism instance does it (classpath and arguments in
`run_client_j25.ps1`).

- **Blocker found: CustomMenu.** The first two boots hung for 10 minutes in mod
  construction. `jstack` shows the client thread inside
  `SDL_SetWindowIcon` ← `Display.setIcon` ← `mainmenuserver.RDMenuServer.<clinit>`.
  With CustomMenu set aside the client booted to the title screen in 61 s
  (Java 8 Angelica: 73–80 s in today's runs). The fix is a one-site
  transformer, ~1 h.
- **OpenAL: pass.** `/jb tone` and `/jb play` both reach `PLAYING`, and

### Test 4: 3 GB flight run. The "Angelica is slower at 3 GB" result is an artifact

Same harness as the 2026-10-16 low-end runs (`run_bench_lo.ps1`, shaders off,
`-Xmx3072M`, 2560×1440), alternating A, B, A, B, A, B.

| Run | E7 static | E7 fly | Angelica static | Angelica fly |
|---|---|---|---|---|
| 1 | 407 (94) | 312 (64) | 239 (76) | 240 (81) |
| 2 | 446 (103) | 339 (74) | 239 (74) | 241 (79) |
| 3 | 446 (102) | 330 (78) | 240 (82) | 240 (78) |

Mean fps with the 1% low in brackets. E7 fly: 312–339, spread 27. Angelica fly:
240–241, spread 1.

Every Angelica scene sits at exactly 240 fps with a median frame of 4.16 ms.
This PC's monitor runs at 240 Hz. That is a refresh-rate cap, not the
renderer's speed, and it also explains the original single run (282 fps, median
4.14 ms). A 7 GB control run showed the same cap during the static scene
(295 fps, median 4.03 ms) and then lifted during the flight, which ran at
1,060 fps (median 0.69 ms). The cap comes and goes within a run, so it's
presentation (window/compositor vsync) rather than heap or CPU.

What can be compared: Angelica's 1% lows (78–81 fps flying) match or beat E7's
(64–78), its worst frame is 31–34 ms against E7's 48–58 ms, and it has 0–1
frames over 33 ms per scene against E7's 2–4. So nothing points to a 3 GB
penalty, and the "possibly GC pressure" note can be dropped. Two caveats
follow. First, the earlier shader-on numbers (Angelica + Vibrant 252–264 fps,
Complementary 239–249 fps) sit at the same ceiling, so Angelica's 1.7–3.9×
advantage is a lower bound. Second, to measure Angelica's true low-end fps the
harness has to force vsync off at the driver; that wasn't done unattended.

### Test 5: the Lucky Block patch. Pass, committed

`mods/qf-tweaks/src/com/questforge/LuckyScriptTransformer.java` and
`LuckyScriptFix.java`, registered in `QuestForgeCore` (commit bdfa4e1). It
inserts one `INVOKESTATIC LuckyScriptFix.loader` before the
`ScriptEngineManager(ClassLoader)` constructor in
`mod.lucky.util.ExpressionParser`. `loader` returns the argument unchanged
unless it is null and the JDK has no JavaScript engine; then it returns the
game's class loader, which sees lwjgl3ify's Nashorn.

- Java 8 server (`trial-base`): boots, logs "the JDK has a JavaScript engine;
  using it unchanged", 0 expression errors, the same as before. Inert.
- Java 25 server (`trial-c`): 301 `ExpressionParserException` lines at boot
  become 0.
- Java 25 client, in game: three Lucky Blocks broken with creative drops
  enabled produced 3 items, a ring of witches and bats, and 14 items. 0
