## Quest book for existing worlds

BetterQuesting copies `config/betterquesting/DefaultQuests.json` into a world only when the
world is created. Worlds made before this batch keep the old book (308 quests). No existing
save was touched.

To load the new book into an existing world, open that world, or join the server as an op,
and run:

```
/bq_admin default load
```

What it does, read from BetterQuesting 3.0.328's `QuestCommandDefaults` and tested in a fresh
trial world:
- It saves every player's quest progress, replaces the world's quests and quest lines with
  `DefaultQuests.json`, then restores the saved progress by quest ID.
- Quests that keep their ID keep their completion. In the test, quest 0 was completed with
  `/bq_admin complete 0 Dev`, the book was reloaded, and quest 0 was still complete.
- Progress on a quest whose ID no longer exists is dropped. Changed tasks start from what the
  saved progress says.
- It also keeps the world's own edit-mode and hardcore settings.

Back the world up first. It changes the world's quest data in place, and the only undo is the
backup. On the server, run it from the console or as an op once the server is up. In
singleplayer the world needs cheats on (or "Open to LAN" with cheats).

## Traps found tonight

- `/kill @e[type=Item]` on 1.7.10 ignores `type=` and kills the player too.
- A probe cannot mine in survival (see Bountiful above). Creative `break` works.
- In offline mode, `op <name>` stores the Mojang UUID for that name, exactly like
  `whitelist add`, so the offline player is not op. Write ops.json with the offline UUID, or
  extend the builder's `--player` to ops.
- An auto-joining client stops the menu music right after the splash (`menu stopped at 0.4s`):
  it is already connecting. Not a regression.
